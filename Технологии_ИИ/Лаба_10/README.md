## Запуск

Нужны правила из соседней Лаба_9, PostgreSQL с уже загруженной схемой dwh работы 6:

~~~bash
pip install pandas numpy sqlalchemy psycopg2-binary matplotlib python-docx
# DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD — как в работе 6
python test_inference.py
python evaluate.py
python make_report.py
~~~

В подготовленной облачной среде:

~~~bash
source /workspace/laby-env/activate.sh
bash /workspace/laby-env/start-db.sh
~~~

evaluate.py выполняет только чтение БД. Перезагружать dwh не нужно.
Отчёт использует Лаба_9/img/rule_flow.png: сначала выполните diagrams.py в работе 9.
Для PDF нужен soffice.

## Результаты

- TP 275, TN 9661, FP 0, FN 64.
- Accuracy 99,36%; precision 100%; recall 81,12%; F1 89,58%.
- С зоной TWF в бинарном прогнозе: TP 320, FP 671, FN 19; F1 падает до 48,12%.
- Разобраны UDI 3237 (граница HDF), 78 (TWF), 1438 (неуказанный тип отказа).
- Это воспроизведение закономерностей синтетического датасета, а не независимая оценка предсказания будущих отказов.
- Целевые метки и результаты классификации из БД в факты не передаются.
- Пустые/нечисловые входы и значения вне диапазонов отвергаются.

## К защите

1. **Прямой вывод:** сопоставить → выбрать → применить до неподвижной точки.
2. **Обратный вывод:** проверяет заданную цель; прямой удобнее для мониторинга.
3. **Трасса:** условия, значения, конфликтное множество и отклонённые заключения.
4. **F1:** гармоническое среднее precision/recall; важно при редких отказах.
5. **Ошибки:** неполнота симптомов, погрешности на границах, стохастические причины и разметка.
