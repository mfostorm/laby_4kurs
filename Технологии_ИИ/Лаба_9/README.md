# Лабораторная работа 9. Разработка базы продукционных правил

**Статус:** выполнена. Вариант 10: предиктивное обслуживание оборудования.
Отчёт: Отчёт_Лаба_9_Вариант_10.docx / .pdf. Исходное задание: Задание 9.pdf.

Номер соответствует имени присланного файла; в тексте методички осталось «занятие 11».

| Файл | Содержимое |
|---|---|
| features.json | 19 входных признаков, диапазоны, источники в PostgreSQL |
| rules.json | 24 правила в четырёх группах, приоритеты и основания |
| actions.json | Расшифровка кодов рекомендаций |
| test_cases.json | 18 примеров с вручную заданными ожидаемыми правилами и заключениями |
| rulebase.py | Загрузчик, проверка структуры, условий и входных фактов |
| diagrams.py, img/ | Группы и схема стадий |
| results/validation.json | Проверка структуры и 18 тестов диагностики |
| make_report.py | Сборка отчёта общим модулем tools/docx_report.py |

## Запуск

Из папки Лаба_9; БД не требуется:

~~~bash
pip install pandas sqlalchemy psycopg2-binary matplotlib python-docx
python -m json.tool rules.json
python rulebase.py
python diagrams.py
python make_report.py
~~~

Для диаграммы нужен Graphviz (dot), для PDF — LibreOffice (soffice).

## Главное

- Три стадии: признаки → риск → рекомендация. Порядок: приоритет, специфичность, ID.
- PWF/OSF/HDF используют прежние пороги AI4I из хранилища.
- TWF 200–240 мин — предупреждение, а не достоверный диагноз.
- Запасы 500 Вт / 1000 мин·Н·м и износ 180 мин — явно обозначенные учебные эвристики.
- Метки отказов не входят во входные факты.
- Все 18 проверок диагностики пройдены. Полный вывод и свидетели для всех 24 правил проверяются в работе 10.

## К защите

1. **Продукционная система:** база правил, рабочая память, механизм вывода, объяснения.
