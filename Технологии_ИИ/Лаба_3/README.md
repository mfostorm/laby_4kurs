## Главное
- Выбрана стратегия **ETL**: трансформации сложные и условные, объём данных небольшой, хранилище — локальный PostgreSQL, и в него должны попадать только проверенные данные.
- Порядок шагов: переименование → текст → типы → диапазоны → дубликаты → пропуски → флаги выбросов → разметка → признаки → валидация.
- Стратегии заполнения пропусков выбраны по данным: температуры — интерполяция (автокорреляция 0,999), момент — через мощность (M = P/ω), износ — по нормативному шагу 2/3/5 мин, обороты — медиана по классу.

## К защите: контрольные вопросы
1. **Чем ETL отличается от ELT?** В ETL данные преобразуются до загрузки, вне хранилища (у нас — в Python). В ELT сырые данные сначала загружаются, а преобразуются уже внутри хранилища средствами SQL.
2. **Когда что применять?** ETL подходит для небольших и средних объёмов, сложной логики, слабого хранилища и требования «в хранилище только чистые данные». ELT — для больших объёмов, мощных облачных/MPP-хранилищ и для случаев, когда нужно хранить сырьё для повторной обработки.
3. **Staging area** — промежуточная зона с неизменяемой копией сырых данных. Позволяет повторить трансформации без повторного извлечения, сверить результат с источником и понять по MD5, какой файл обрабатывался.
4. **Стратегии обработки пропусков:** удаление строк; заполнение константой, средним, медианой или модой (в том числе внутри группы); предыдущим значением; интерполяцией; по связи с другими признаками; флаг «было пропущено».
5. **Идемпотентность:** детерминированные трансформации, фиксированные параметры (границы IQR не пересчитываются на каждой партии), перезапись результата целиком, загрузка одной транзакцией, регистрация партии по MD5 с ограничением UNIQUE.
